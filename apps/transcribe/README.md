# Bass Transcribe Lab V1.0

面向贝斯扒谱与教学的本地练习工作台。独立项目；不依赖或修改 Bass Shape Lab。

导入自己设备上的音频或带音轨的视频，查看真实波形、选择 A/B 区间、循环练习，独立控制速度与音高。音频解码、处理和歌曲保存均在浏览器本地完成。没有账户、后端、歌曲上传、远程字体或付费服务。

## 启动与构建

本目录已包含构建好的 `dist/`。在此 Mac 上可运行 `打开预览.command` 启动本地版本（需要 Python 3），无需先安装开发依赖。

开发环境需要 Node.js 22.13 或更新版本，以及 pnpm。首次安装开发依赖需要联网，构建后的运行不依赖 CDN。

```sh
pnpm install --frozen-lockfile
pnpm dev
```

打开终端显示的本地网址。生产构建与预览：

```sh
pnpm build
pnpm preview
```

`build` 包括 TypeScript 检查、Vite 构建和离线缓存生成。PWA 与离线模式只在生产构建预览或正式静态托管中启用；开发模式不注册离线缓存。不要直接双击 `dist/index.html`：Web Audio Worklet 与 Service Worker 需要本地 HTTP 或 HTTPS 环境。

## 常用操作

- 导入按钮或将本地文件拖入页面。格式能否导入，以当前浏览器实际解码结果为准。
- 单击波形定位；双击从该位置播放；在波形上拖拽创建 A/B 选区。
- 拖动 A/B 边界调整循环；拖动选区移动手柄整体移动；放大后可滚动查看细节。
- 速度与音高分别调整。原音、升高一八度、升高两八度用于辨认低音；EQ 用于调整听感。
- 暂停自动回退默认关闭，可设为 1–3 秒；循环间隔与快退/快进步长可设置。
- 每首歌保存自己的播放位置、速度、音高、A/B 区间和段落标记。

| 快捷键 | 操作 |
| --- | --- |
| Space | 播放 / 暂停 |
| ← / → | 按常规步长回退 / 前进，默认 3 秒 |
| Shift + ← / → | 按精细步长回退 / 前进，默认 1 秒 |
| A / B | 将当前位置设为循环起点 / 终点 |
| L | 循环开关 |
| Esc | 退出当前循环 |
| ↑ / ↓ | 速度增加 / 减少 5% |
| R | 原速与设定的练习速度切换 |
| O | 原音 → +1 八度 → +2 八度循环切换 |

输入框、下拉框和其他可编辑控件中的输入优先；带 Ctrl / Command / Alt 的系统组合键不被播放器接管。

## 格式与设备限制

文件扩展名不代表能解码。应用使用浏览器 `decodeAudioData`，不捆绑通用媒体转码器：MP3、WAV、FLAC 和视频容器中的音轨均取决于浏览器、系统编解码器、文件内容及是否受保护。没有音轨、损坏、加密或不受支持的文件会显示解码失败信息，不会伪装成导入成功。

V1 将整首音频解码到内存。本版处理单声道/立体声；超过两声道会明确拒绝，不会静默丢弃额外声道。文件上限180 MB，解码PCM上限256 MB；这些检查不能保证所有手机都不会在完整解码过程中内存不足。较长、高采样率文件可能超过设备内存；手机尤其需要从短片段开始。独立变速变调仍可能引入瞬态、音色和极低速度伪影。原速原音采用透明 PCM 直通；半速/+12组合实测约10.8音分的算法偏差，完整记录保留严格±1Hz失败及官方对照。实际设备、格式与 DSP 测量结果见 [测试记录](docs/TESTING.md)。

## 本地保存、恢复与删除

歌曲元数据与原文件副本保存在当前网址的 IndexedDB 中。歌曲库列表只读取元数据，避免一次载入全部音频。若浏览器允许，应用可申请持久存储；浏览器有最终决定权，申请不代表永久保留。

空间不足时会尝试只保存练习参数，并提示下次重新选择原文件。若元数据也无法保存，会明确显示失败；当前会话仍可练习。歌曲库删除操作同时删除该歌曲的原文件副本和练习数据；晚到的自动保存不会重新创建已删除歌曲。

浏览器清理网站数据、隐私模式结束、存储回收、更换浏览器或网址均可能让歌曲库不可用。请保留自己的原文件。本地保存不是跨设备同步或云端备份。

## 离线与安装

联网首次完整打开生产版，并等待页面提示离线资源就绪后，即可在断网情况下重新打开。音频必须已经保存在此设备的歌曲库，或断网后重新从设备选择。离线缓存包含页面、脚本、图标和 DSP 所需资源；不缓存远程服务，不上传本地歌曲。

支持安装的浏览器可使用地址栏安装入口；移动 Safari 可尝试“添加到主屏幕”。是否显示安装入口以及后台播放行为由设备和浏览器决定，本项目不承诺未经测试设备的表现。

新版本会先完整缓存，播放中的页面不会被强制重载。正常刷新会优先取得新版；如果页面显示“更新”按钮，可点击后保存进度并刷新。断网时使用已完整缓存的版本，不需要清除歌曲或网站数据。

## GitHub Pages 与静态部署

GitHub Pages 自动发布配置已包含在 `.github/workflows/deploy-pages.yml`；首次启用步骤和发布检查见[部署说明](docs/DEPLOYMENT.md)。配置就绪不代表已经上线，以远端运行结果与实际网址为准。

将 `dist/` 中全部文件原样放入支持 HTTPS 的静态托管目录。可部署在站点根目录或独立子目录，例如 `https://example.com/bass/`；子目录地址应以 `/` 结尾。Vite 使用相对资源路径，Service Worker 与 manifest 使用当前目录作为作用域。

托管必须返回正确内容类型，尤其是 `sw.js` 的 JavaScript 类型；不得将缺失脚本重写成 HTML。建议 `index.html`、`sw.js` 和 manifest 使用可重新验证缓存；带 hash 的 `assets/` 可长效缓存。发布必须一并上传新的所有资源，避免先替换页面却缺少脚本。

运行时资源均随静态构建本地化，可选择适合中国大陆用户的静态托管。是否需要备案、实际网络可达性和速度由所选托管及域名决定。本项目没有因此自动购买域名、开通付费服务或验证中国大陆部署访问；以实际部署与实测报告为准。

## 节点、循环与段落

- “添加标记”按钮保持同名，旁边选择“节点标记”或“范围标记”。
- “节点”tag位于“段落”左侧，默认折叠并显示数量；展开可查看、定位、改名和删除节点。
- 节点标记记录单个歌曲位置，以细线和小旗显示。点击定位并打开名称编辑；可拖动、改名或删除，不会自动配对为循环。新增或移动节点不会改动已有循环和段落。
- 范围标记在两个播放位置各添加一次，形成绿色临时循环；也可直接拖选波形，拖A/B边界或顶部选区整体调整。
- “段落”tag默认折叠。打开后可将当前绿色循环保存并命名；所有已保存段落始终以橙色范围显示在波形内部。
- 点击橙色段落立即进入该范围循环播放。之后拖动绿色循环不会改变橙色段落；删除橙色段落也不会删除当前绿色循环。
- 点击没有橙色段落的波形空白、循环旁的×或按Esc，退出绿色循环；橙色段落与节点继续保留。点击节点会退出当前循环并定位到该节点。
- 放大后使用手形开关平移，桌面也可按Shift或鼠标中键拖动；边界拖到视口边缘会自动滚动。
- “R 练习速度”单独设置并按歌曲保存；调整当前速度不改变R目标。R从非原速回到原速，再按回到设定练习速度。
- O依次为原音、+1八度、+2八度；当前为细调值时，先回原音。
- 旧点标记按既有兼容规则恢复为段落，新节点单独存储；歌曲与音频Blob保持原样。

缓存更新记录见docs/UPDATE-CACHE-RESULTS.md；本轮交互记录见docs/INDEPENDENT-MARKS-RESULTS.md与docs/INDEPENDENT-TOUCH-RESULTS.md。
