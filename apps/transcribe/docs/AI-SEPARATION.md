# AI 分轨独立技术验证路线

状态：**规划，未接入 V1，也未声称已完成浏览器推理实验。**

目标是在用户设备上产生贝斯、人声、鼓与其他伴奏音轨。先建立独立实验目录或项目，不改变正式播放器依赖、离线缓存大小或启动过程。正式 V1 的音频导入、DSP 和循环练习不依赖模型。

## 建议验证顺序

1. **固定可复现基准**：选择有明确许可的短音乐片段及各自干净音轨，记录采样率、声道、时长。不得把用户歌曲上传到外部推理服务。
2. **先跑桌面参考**：选定模型、权重来源和许可证，使用官方或可核对的参考实现生成结果。模型代码许可不能代替权重或训练数据许可审查。
3. **单独验证浏览器后端**：在独立页面验证 ONNX Runtime Web/WebGPU 或其他明确支持的本地推理后端；先确认所需算子、模型导出一致性、浏览器与设备能力，再讨论界面接入。
4. **分块与内存测试**：逐步从短片段扩展，记录冷启动、模型下载与本地缓存大小、峰值内存、处理耗时、接缝和输出对齐。保留取消、资源释放、失败恢复与无 GPU 的明确提示。
5. **比较分离质量**：对照参考输出听检低音、鼓低频串音、瞬态和相位；有真值时再计算数值指标。不要以成功加载模型代替分离质量验证。
6. **离线与设备矩阵**：模型资源经用户主动选择后在本地保存；测试缓存不足、取消下载、浏览器清理及真实移动设备。正式主应用启动不应被模型加载拖慢。
7. **达到门槛后再设计接入**：先明确许可、目标设备、内存和耗时预算、分离质量、离线稳定性，再决定做独立工具还是可选模块。需要付费或远程服务时另行说明并获得授权。

## 一手技术资料

- [Demucs 官方研究代码](https://github.com/facebookresearch/demucs)：原仓库已归档，可作为参考与基准入口；选用实现时需要评估维护状况和具体权重来源。
- [ONNX Runtime WebGPU 官方说明](https://onnxruntime.ai/docs/tutorials/web/ep-webgpu.html)：用于查验浏览器推理后端的使用条件和限制。它不能单独证明某个分轨模型已经兼容。

上述路线只提出验证工作；模型体积、速度、兼容设备和音质均应由实际实验结果确定。
